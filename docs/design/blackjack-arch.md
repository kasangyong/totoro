## 결정 1. 돈 흐름 (하우스 정산)

섯다·포커는 판 안에서 스택 합이 보존되지만, 블랙잭은 하우스가 이기거나 지므로 판마다 스택 합이 바뀐다.

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. 테이블 스택 유지 + 판 끝에 정산 함수가 스택 변경과 정산 기록을 함께** | 착석·바이인·일어서기가 섯다·포커와 같다. 판 도중 지갑을 안 건드려 혼자 하는 게임과 경합 없음 | 정산표·함수 추가, 보존식이 게임별로 달라짐 |
| B. 지갑에서 바로 베팅 (`bj_bet`·`bj_payout` 원장) | 원장만으로 추적 | 더블·스플릿마다 판 도중 지갑 차감 → 솔로 게임과 잔액 경합, 방 UI 흐름이 달라짐 |
| C. 원장에 하우스 kind 추가 | 원장 한 곳 | `ledger.balance_after`(지갑 잔액)와 뜻이 어긋나고, 일어설 때 `table_cashout`이 승리분을 한 번 더 세어 이용자별 `Σ원장 = 지갑`이 깨짐 |

**추천: A.**
- 새 테이블 `private.house_settlements(hand_id, user_id, seat_session_id, bet_total, delta, kind, created_at)`, `unique(hand_id, user_id)`. `kind`는 `'settle'`(정상 종료) 또는 `'void'`(방치 청소)이다.
- 판 종료 시 **스택을 직접 UPDATE하지 않는다.** 정산 함수 하나가 원자적으로 처리한다.
  - `private.settle_blackjack_hand(p_hand uuid, p_rows jsonb)`, SECURITY DEFINER. 각 행은 `{user_id, bet_total, delta}`이다.
  - `hands.status = 'playing'`인지 확인하고, 그 판 좌석을 `FOR UPDATE`로 잠근다(기존 잠금 순서 유지).
  - 그 판 참가 좌석(`hand_start_stack is not null`) **전부**를 정리한다. 넘어온 행이 정확히 그 좌석들이어야 하고(불참 = `bet_total 0, delta 0`), 행마다 `bet_total = room_seats.hand_contrib`, `bet_total ≤ hand_start_stack`, `−bet_total ≤ delta ≤ 1.5 × bet_total`을 검사한다. 어기면 예외.
  - `stack = hand_start_stack + delta`, `hand_start_stack = null`, `hand_contrib = 0`으로 바꾸고 정산 행을 insert한다(unique로 이중 정산 차단). **`(user_id, stack)` 목록을 돌려주고, 서비스는 그 값으로 `ctx.seats`를 갱신한 뒤** 판 끝 자동 일어서기·cashout을 한다.
  - 권한: `revoke execute ... from public, anon, authenticated` 후 `grant execute ... to engine_rw`.
  - 한계: `engine_rw`는 섯다·포커 때문에 `room_seats` UPDATE 권한을 이미 갖고 있다. 이 함수는 정상 경로를 원자화하고 범위를 검사하는 장치이지, 엔진 코드를 불신하는 장치는 아니다.
- **원장(`ledger`)·지갑은 판에서 건드리지 않는다.** 일어설 때 `table_cashout`이 스택 전부를 지갑으로 돌려준다(기존 그대로).
- 보존 불변식은 게임별로 쓴다. `rooms-arch.md`도 같이 고친다.
  - 섯다·포커 방: `Σ원장(table_*) = −Σroom_seats.stack` (기존)
  - 블랙잭 방: `Σ table_buyin − Σ table_cashout + Σ house_settlements.delta = Σ room_seats.stack`. 판 도중에는 `hand_start_stack` 기준이다.
  - 이용자별 `Σ원장 = 지갑`은 모든 게임에서 유지된다.

### 방치 무효 악용 막기 (평가 1차 "위험" 1번)
`tick`은 참가자 브라우저가 부른다. 혼자 앉아 나쁜 패를 받고 탭을 닫으면, 10분 뒤 청소가 판 시작 스택으로 되돌려 **지는 판만 무를 수 있다**.

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. 블랙잭 판에서 걸린 금액을 `room_seats.hand_contrib`에 실시간 기록, 청소 시 그 금액을 몰수(`kind='void'`, `delta = −hand_contrib`)** | SQL만으로 처리, 새 인프라 없음, 악용 이득 0 | 실수로 창을 닫아도 건 돈을 잃음 → 규칙과 화면에 고지 |
| B. 서버가 직접 tick (pg_net·cron 라우트) | 판이 끝까지 진행됨 | 외부 호출 인프라 추가, 1분 단위라 느림 |

**추천: A.**
- 베팅·더블·스플릿 액션 트랜잭션에서 `room_seats.hand_contrib`를 누적 걸린 금액으로 갱신한다(섯다·포커는 계속 0).
- `close_abandoned_rooms`의 블랙잭 분기: `hand_start_stack is not null`인 좌석마다 `stack = hand_start_stack − hand_contrib`로 바꾸고, `house_settlements`에 `('void', −hand_contrib)`을 insert한 뒤 cashout한다. 섯다·포커 분기는 그대로 둔다.
- 다시 접속하면 브라우저가 기한을 보고 `/tick`을 불러 이어서 진행된다(기존과 같음). 몰수는 10분 동안 아무도 없을 때만 일어난다.

## 결정 2. 판 진행 단계

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. seeding → betting(동시) → deal → peek → 좌석 순서 턴 → dealer(자동) → done** | 카지노 진행 그대로, 베팅을 다 받은 뒤 딜하므로 커밋 흐름 유지 | 베팅 단계 대기 |
| B. 앉을 때 고정 베팅액 | 대기 없음 | 판마다 금액 조절 불가 |

**추천: A.**
1. **seeding**: 기존과 같다.
2. **betting** (동시, 기한 `BET_MS` = 15초, 기존 `CHOICE_MS`와 같은 값): 각자 `bet(amount)` 또는 `sit_out`(이번 판 쉬기)을 낸다. 낸 값은 바로 공개된다.
   - 베팅 범위: `기본금 ≤ amount ≤ min(기본금 × 20, 스택, MAX_BET)`, **짝수만** 받는다(3:2를 정수로 정확히 지급하려고). `MAX_BET`은 솔로 게임과 같은 `lib/engine/solo/games.ts`의 상수(1,000,000)이다. 블랙잭 방은 기본금도 짝수, 10P 이상이어야 한다(서비스와 DB 체크 둘 다).
   - 기한 안에 아무것도 안 내면 `bet_timeout`으로 불참 처리하고 timeout으로 센다. 그 판에 본인 액션이 없었으므로 기존 idle 규칙대로 판 끝에 자동으로 일어선다. `sit_out`은 본인 액션이라 자리를 지킨다. 일어서기를 눌러 `away`가 된 좌석은 베팅 단계에서 자동으로 `sit_out` 처리한다(기다리지 않음).
   - 전원이 정하면 기한 전이라도 바로 딜한다. 한 사람이 정해도 기한은 늘어나지 않는다(초이스와 같은 동시 선택 처리). 베팅한 사람이 0명이면 딜 없이 끝내되, 정산 함수는 그대로 부른다(전원 `0, 0` → `hand_start_stack` 정리).
3. **deal**: 좌석 순서로 1장씩 → 딜러 오픈 → 좌석 순서로 1장씩 → 딜러 히든.
4. **peek**: 딜러 오픈이 A나 10점이면 히든을 확인한다.
   - 딜러가 블랙잭이면 즉시 정산한다. 참가자 블랙잭은 푸시, 나머지는 원 베팅을 잃는다.
   - 딜러가 블랙잭이 아니면, 블랙잭인 참가자는 **턴 없이 3:2로 확정**된다.
5. **turn**: 좌석 번호 순서이고, 스플릿한 사람은 손 1 → 손 2 순서다. `toAct = { seatId, handIdx }`.
   - 액션: `hit` · `stand` · `double` · `split`. 기한은 `TURN_MS`이고, **차례(`toAct`)가 바뀔 때마다 새로 잡는다**(스플릿 손 2도 새 기한). 시간 초과는 `stand`이다.
   - 21이 되거나 버스트하면 자동으로 다음 손으로 넘어간다. 더블은 1장만 받고 끝난다.
6. **dealer**: 리듀서 안에서 한 번에 끝내고 기한을 잡지 않는다. 히든을 공개한 뒤, **버스트도 블랙잭도 아닌 손이 하나라도 있으면** 17 이상이 될 때까지 받는다. 소프트 17이면 멈춘다. 그런 손이 없으면 공개만 하고 받지 않는다.
7. **done**: 정산 함수 호출 → 5초 뒤 다음 판. 딜러와 하는 게임이라 **1명**만 앉아 있어도 시작한다.

## 결정 3. 세부 규칙과 RTP

원칙은 "모든 게임 RTP 99%"이다. 블랙잭은 하우스 엣지가 플레이에 따라 달라진다.

| 옵션 | 기본 전략 기준 하우스 엣지 | 비고 |
|---|---|---|
| **A. 6덱, S17, 3:2, peek, 아무 2장 더블, DAS 허용, 스플릿 1회, A 스플릿은 1장씩** | 약 0.43~0.46% (RTP 약 99.55%) | 가장 흔한 카지노 룰 |
| B. A와 같고 DAS(스플릿 후 더블)만 금지 | 약 0.6% | 설명은 조금 쉬움 |
| C. 6:5 블랙잭 | 약 1.8% | 99% 원칙 위반 → 제외 |

**추천: A.** 규칙 목록:
- **블랙잭** = 처음 2장이 A + 10점 카드. 3:2로 지급하고, 베팅이 짝수라 나머지가 없다.
- **승** 1:1, **푸시**는 돌려받음, **버스트**(22 이상)는 바로 패배(딜러가 나중에 버스트해도 패배).
- **더블**: 손의 처음 2장일 때(스플릿 뒤 손 포함 = DAS) 원 베팅만큼 더 걸고 1장만 받는다.
- **스플릿**: 처음 2장의 **점수가 같으면**(10·J·Q·K끼리도 가능, 대중 룰) 1회만 나눈다. 나눈 손에서 다시 나누기는 안 된다. A를 나누면 각 손에 1장씩만 받고 끝나며, 더블도 못 한다. 스플릿 후 A + 10은 블랙잭이 아니라 21(1:1)이다.
- **스택 조건은 누적 기준**: 더블·스플릿은 `지금까지 건 금액 합 + 추가 금액 ≤ 판 시작 스택`일 때만 가능하다. 스플릿 후 두 손 모두 더블하면 최대 4 × 베팅이다.
- 기본 전략대로 하면 RTP가 99%보다 조금 높고, 감으로 하면 낮다. 규칙 문서와 화면에 "실력이 들어가는 게임"이라고 적는다.

**검증 방법 (평가 1차 6번 반영)**
- 엔진은 poker7처럼 **덱을 인자로 받는다**(`createBlackjackHand(p, deck?)`). 위 규칙마다 고정 덱 시나리오 단위 테스트를 둔다.
- RTP는 단위 테스트가 아니라 별도 스크립트(`scripts/bj-rtp.mjs`)로 잰다. 빠른 PRNG로 덱을 섞고, 이 룰(6덱 S17·DAS·스플릿 1회·peek)용 기본 전략표를 쓰는 봇으로 1,000만 판을 돌린다(표준오차 약 0.035%p). **RTP = 총 지급 ÷ 처음 베팅 합**(더블·스플릿 추가분은 분모에 넣지 않음, 하우스 엣지 관례)이고, 기대 범위는 99.45~99.65%이다. H17 같은 큰 실수를 잡는 용도이고, DAS처럼 작은 차이는 고정 덱 테스트가 맡는다.

## 결정 4. 카드·RNG

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. 판마다 6덱(312장) 새로 섞기, 카드 id 0~311, 무늬·숫자 = `id % 52`** | 카드 카운팅 의미 없음, RNG v1 그대로, 트럼프 그림 재사용 | 매번 312장 셔플(가벼움) |
| B. 슈 연속 사용 | 실제 카지노와 같음 | 판 사이 상태 보관, 판마다 독립 검증 불가 |

**추천: A.** 초기 덱 = 포커 순서(♠2…♠A, ♦…, ♥…, ♣…)를 6번 반복한다. RNG 규격 표에 블랙잭 행을 추가하고, `rematch_no`는 항상 0이다. 검증 페이지는 쓰인 카드까지만 덱 순서를 보여 준다.

## 결정 5. 숨김 정보

- 비밀(`secrets`): 덱, 딜러 히든 카드.
- `viewFor`: 딜러 히든은 공개 전까지 `null`. peek에서 "블랙잭이 아니었다"는 사실은 드러난다(실제 카지노와 같고, 이득 없음).
- 참가자 카드는 전부 공개(원래 앞면으로 딜한다).
- 테스트: 모든 시점의 view JSON과 `room_events.payload`에 히든과 남은 덱이 없는지 검사한다(`tests/rooms.test.ts`의 패턴).
