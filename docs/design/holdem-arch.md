# 설계: 텍사스 홀덤 방

- 작성일: 2026-10-02 (rev.2: 1차 평가 "보통" 반영. 올인 우회, 행동자 1명, 짧은 블라인드·첫 벳, 레이즈 경계, 버튼 좌석 저장, 연결 지점 목록, 공개 범위 고지)
- 관련 문서: [방 설계](rooms-arch.md) · [게임 규칙](card-games-rules.md) · [3장 섯다 설계](sutda3-arch.md)(방식 선택) · [블랙잭 설계](blackjack-arch.md)(어댑터, 금액 액션)
- 사용자 확정 사항: 홀덤을 **설계부터 끝까지** 만든다. 방을 만들 때 포커를 고르면 방식에서 세븐포커/**홀덤**을 고를 수 있다(지금은 "준비 중"으로 표시됨).
- 출처: 국내 포커 앱과 국제 표준 모두 **노리밋 텍사스 홀덤**을 쓴다. 블라인드 2개, 개인 카드 2장, 공용 카드 5장, 베팅 4번(프리플랍·플랍·턴·리버), 7장 중 가장 좋은 5장으로 겨룬다([wikidocs](https://wikidocs.net/274413), [gaming.net](https://www.gaming.net/ko/how-to-play-texas-holdem/)). 세부 규칙은 국제 표준(TDA)을 따르고, 다르게 정한 점은 **[우리 규칙]**으로 표시한다.

## 결정 1. 베팅 방식

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. 노리밋 + 블라인드(SB·BB), 레이즈 금액을 직접 정함** | 홀덤 표준이고 국내 앱도 이 방식이다. | 새 베팅 모듈과 금액 입력 화면이 필요하다(블랙잭 베팅 UI를 재사용). |
| B. 기존 한국식 팟 베팅(삥·따당·하프) | 기존 코드를 재사용한다. | 블라인드가 없어 홀덤이라고 하기 어렵다. |
| C. 팟 리밋 | 큰 판이 줄어든다. | 덜 대중적이다. |

**추천: A.** 엔진은 `lib/engine/holdem/game.ts`에 새로 만든다. 기존 `betting.ts`의 라운드 로직은 쓰지 않고, 팟 계산 함수 `computePots`·`awardPots`만 재사용한다.

### 블라인드·순서
- **BB = 방 기본금**, **SB = 기본금의 절반(내림, 최소 1)**. 홀덤 방의 기본금은 2 이상이다. 앤티는 없다.
- 블라인드를 내는 것은 행동으로 치지 않는다(`acted = false`).
- **프리플랍** 시작 때 `currentBet = BB 금액`(BB가 짧아 올인했어도 콜 금액은 BB 전액), `minRaise = BB`. **플랍 이후** 라운드마다 `currentBet = 0`, `minRaise = BB`, 모두 `streetContrib = 0`·`acted = false`로 시작한다.
- 스택이 블라인드보다 적으면 가진 만큼만 내고 올인이 된다. 실제로는 판 시작 조건(스택 ≥ 기본금, service `eligibleSeats`) 때문에 짧은 블라인드는 생기지 않는다. 엔진은 방어적으로 처리하고, 테스트는 엔진에 스택을 직접 넣는 단위 테스트로 둔다.
- **딜러 버튼은 좌석 번호로 저장한다.** 방 상태에 `buttonSeatNo`를 두고, 판이 시작될 때 이번 참가자 중 그보다 좌석 번호가 큰 첫 사람(한 바퀴 돌아 처음으로)을 버튼으로 정한다. 첫 판은 방장이 참가하면 방장, 아니면 가장 낮은 좌석이다.
  - 버튼이 사람이 아니라 좌석을 따르므로, 판 사이에 일어서거나 새로 앉아도 자연스럽게 다음 좌석으로 넘어간다.
  - **[우리 규칙]** 데드 버튼은 쓰지 않는다. 인원이 줄면 같은 사람이 BB를 연달아 낼 수도 있다.
- 3명 이상일 때: 버튼 왼쪽이 SB, 그 왼쪽이 BB다. 프리플랍은 BB 왼쪽부터, 플랍부터는 버튼 왼쪽의 살아 있는 사람부터 행동한다.
- **헤즈업(2명)**: 버튼이 SB를 내고 프리플랍에 먼저 행동한다. 플랍부터는 BB가 먼저다.
- **카드 돌리기**: 버튼 왼쪽부터 한 장씩 두 바퀴(표준대로 헤즈업이면 BB부터, 버튼이 마지막). 공용 카드는 번 1장 → 플랍 3장, 번 1장 → 턴, 번 1장 → 리버.

### 액션 (`{ type: "act", seatId, action, amount? }`, 시간 초과는 `{ type: "timeout", seatId }`)
- 기호: `toCall = currentBet − streetContrib`, `maxRaiseTo = streetContrib + stack`, `minRaiseTo = currentBet + minRaise`
- `respond`: 나 말고 행동할 수 있는 사람(살아 있고 올인이 아닌 사람)이 있는가
- `fold`: 언제나 가능하다.
- `check`: `toCall = 0`일 때.
- `call`: `toCall > 0`일 때. 스택이 모자라면 올인 콜이 된다.
- `raise`(총액 X): `!acted`이고, `respond`이고, `maxRaiseTo ≥ minRaiseTo`일 때. `minRaiseTo ≤ X ≤ maxRaiseTo`이고 `X = maxRaiseTo`이면 올인이다.
  - 아무도 걸지 않은 라운드의 첫 벳도 같은 규칙이다. 0에서 올리는 레이즈로 보고, 최소액은 `0 + BB = BB`다.
- `allin`: `!acted`이고, `respond`이고, `stack > toCall`일 때(콜보다 많이 거는 올인).
  - 증가분이 `minRaise` 이상이면 **완전한 레이즈**다. `minRaise = 증가분`으로 바꾸고, 다른 사람들의 `acted`를 지운다.
  - 증가분이 그보다 작으면 **짧은 올인**이다. `currentBet`만 올리고 `minRaise`와 다른 사람의 `acted`는 그대로 둔다. 이미 행동한 사람은 콜이나 폴드만 할 수 있다.
  - 첫 벳이 BB보다 적은 올인이면: `currentBet = 그 금액`, `minRaise = BB` 유지. **[우리 규칙]** 다음 사람의 최소 레이즈는 `그 금액 + BB`다(TDA의 "완성(complete)"은 따로 두지 않는다).
  - 이미 행동했는데 짧은 올인을 마주한 사람은 `allin` 버튼을 쓸 수 없다. 스택이 콜 금액보다 적으면 `call`이 곧 올인 콜이다. 이렇게 짧은 올인 규칙을 우회하는 길을 막는다.
  - **[우리 규칙]** 짧은 올인이 여러 번 겹쳐 완전한 레이즈 크기가 되어도 레이즈 기회를 다시 열지 않는다.
- **모든 행동**(check·call·fold·raise·allin·timeout) 뒤 그 사람은 `acted = true`. 완전한 레이즈(또는 완전한 올인)면 폴드·올인이 아닌 **다른 사람**의 `acted`를 지운다.
- **엔진이 금액 범위를 직접 검사한다.** 서비스도 미리 검사하지만, 검증 페이지에서 재생할 때도 같은 판정이 나와야 하기 때문이다(블랙잭과 같다).

### 라운드·판 종료
- **라운드 종료**: 행동해야 할 사람이 없으면 끝난다. 행동해야 할 사람은 살아 있고, 올인이 아니고, `!acted`이거나 `streetContrib < currentBet`인 사람이다. 예외로, 행동할 수 있는 사람이 **1명뿐이고 그 사람이 최고액 이상을 냈으면** 바로 끝난다(기존 betting.ts의 규칙과 같다).
- **라운드를 시작할 때** 행동할 수 있는 사람이 1명 이하면 베팅 없이 남은 공용 카드를 모두 깔고 쇼다운한다(런아웃).
- **한 명만 남으면** 그 사람이 팟을 가져가고 패를 보여 주지 않는다. `result.hands`는 비운다.
- **시간 초과**: 체크할 수 있으면 체크, 아니면 폴드.
- 콜되지 않은 초과분은 기존 `computePots`가 그 사람만 자격 있는 팟으로 만들어 돌려준다.

### 쇼다운·팟
- 살아 있는 사람 전원의 패를 공개하고, 7장 중 가장 좋은 5장(결정 2)으로 겨룬다.
- 점수가 같으면 **나눈다**. 사이드팟은 기존 `computePots`·`awardPots`로 처리한다.
- **[우리 규칙]** 나누고 남는 칩은 좌석 번호가 가장 낮은 수령자가 받는다(모든 방 게임 공통).
- `result.hands`에는 **쇼다운한 사람만** 넣는다(공개 컬럼이므로).
- **공개 범위 고지**: 판이 끝나면 검증을 위해 덱 전체가 공개된다. 그래서 폴드한 사람이나 혼자 남아 이긴 사람의 개인 카드도 그때 드러난다. 섯다·포커와 같은 방식이다. 규칙 문서와 검증 페이지에 적어 둔다.

## 결정 3. 엔진 상태와 숨김 정보

- `HoldemState`
  - `game: "holdem"`, `handId`, `baseBet`
  - `buttonId`, `sbId`, `bbId`
  - **`phase`**: `"preflop" | "flop" | "turn" | "river" | "done"` (어댑터의 `phase === "done"` 검사와 맞춘다)
  - `seats: { id, seatNo, stack, handContrib, streetContrib, folded, allIn, acted }`
  - `currentBet`, `minRaise`, `toActId`
  - `board: PokerCard[]`
  - `holes: HeldCard[]` (주인에게만 보인다. 쇼다운 때 살아 있는 사람 것만 앞면으로 바꾼다)
  - `result`
  - `secrets: { deck, deckPos }`
- `createHoldemHand(p, deck?)`: 덱을 인자로 받는다(테스트용 고정 덱). 기본 덱은 RNG v1로 섞은 52장이고 초기 순서는 포커와 같다.
- view: `secrets`를 지우고, 남의 개인 카드는 `maskCards`로 `null`이 된다. 공용 카드는 공개다.
- 결과: `payouts`(받은 금액), `winnerId`(메인 팟 승자, 좌석 번호가 가장 낮은 사람), `hands`(쇼다운한 사람의 족보 이름과 쓴 5장).
- 헬퍼 `legalHoldem(state, id)`, `raiseBounds(state, id) → { min, max } | null`: 화면과 서비스가 같이 쓴다.

## 결정 5. 화면 (`holdem-stage.tsx`로 분리, 블랙잭처럼)

- **방 만들기**: 포커를 고르면 방식의 "홀덤"이 켜진다.
- **room-table 분기**: 홀덤이면 카드는 `PlayingCard`로 그린다. 상태 문구는 라운드 이름과 차례이고, 팟은 `handContrib` 합계다. 배지는 `D`·`SB`·`BB`·차례·폴드·올인을 쓴다. 족보 배지는 `result.hands`의 이름이다.
- **테이블 영역**
  - 가운데(데스크톱): 공용 카드 5칸. 아직 깔리지 않은 칸은 빈 테두리다. 라운드 이름도 같이 보여 준다.
  - 다른 사람 자리: 개인 카드 2장(작게)과 이번 라운드에 건 금액.
  - 내 자리: 개인 카드 2장(크게)과 지금 내 족보 이름.
- **내 차례 버튼** (`btn-main` 통일)
  - 폴드, 체크 또는 "콜 N", 레이즈, 올인.
  - 레이즈는 금액 입력과 빠른 버튼(최소, ½ 팟, 팟, 최대)으로 한다. 범위 밖이면 버튼이 꺼진다.
- **족보 패널**: 홀덤 족보를 낮은 것부터 나열하고, 개인 2장 + 깔린 공용 카드로 만든 지금 내 최고 족보를 강조한다. 5장이 안 되면 페어·트리플·포카드·하이카드까지만 판정한다. `hand-ranks.tsx`에 홀덤 분기를 넣고, `myHandLabel`도 같이 바꾼다.
- 데스크톱은 한 화면에 들어가야 하고, 모바일 360·390에서 가로로 넘치지 않아야 한다(공용 5장은 작은 카드로).

## 구현 단계 (단계마다 평가해서 통과해야 다음으로 간다)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| H1 | 엔진(`hands`·`game`) + 테스트 | 아래 고정 사례와 퍼즈 테스트를 모두 통과한다. |
| H2 | 마이그레이션 + 어댑터·서비스·API | 아래 DB 테스트를 통과하고, 기존 DB 테스트도 전부 통과한다. |
| H3 | 화면 + 검증 페이지 + 규칙 문서 | 아래 확인을 모두 통과한다. |
| H4 | 배포 (/careful) | 원격 마이그레이션을 적용하고 운영에서 1판을 해 본다. |

**H1 고정 사례**
- 족보:
  - 키커
  - 투페어 키커, 페어 3개 중 높은 둘을 고르기
  - 휠과 6-하이 스트레이트, 휠 스트레이트 플러시
  - 플러시 > 스트레이트
  - 보드가 스트레이트인데 내 패가 플러시인 경우
  - 보드 포카드에서 키커 비교
  - 풀하우스끼리 비교
  - 보드 플레이 무승부는 나눔
- 진행:
  - 블라인드 금액, 카드 돌리는 순서(헤즈업 포함), 번 카드 위치, 플랍 첫 벳 최소 = BB
  - 3명 순서, 헤즈업의 프리플랍·플랍 이후 순서
  - BB 옵션
  - 최소 벳·최소 레이즈, `X == maxRaiseTo`이면 올인
  - BB보다 적은 첫 올인 벳
  - 짧은 올인은 레이즈를 다시 열지 않음. 이미 행동한 사람은 `raise`·`allin`이 거부됨. 짧은 올인 2번이 겹쳐도 다시 열지 않음([우리 규칙])
  - 완전한 레이즈는 다시 엶
  - 행동할 수 있는 사람이 1명이면 차례를 건너뛰고 런아웃
  - 콜 안 된 초과분 반환, 사이드팟 3단계, 남는 칩은 가장 낮은 좌석
  - 한 명만 남으면 비공개로 끝나고 `hands`가 비어 있음
  - 시간 초과(체크/폴드)
  - 범위 밖 금액 거부
- 퍼즈: 결정성(`replay`), 칩 보존, 남의 개인 카드와 덱이 보이지 않음

**H2 DB 테스트**
- 3명 완주와 보존식
- 레이즈 금액 검증(범위 밖 거부)
- 동시 tick이 한 번만 적용됨
- 남의 카드가 보이지 않음
- 다음 판 버튼 이동(버튼 다음 좌석이 일어섰을 때, 그 사이에 새로 앉았을 때 포함)
- 한 명만 남아 끝났을 때 `result.hands`가 비어 있음

**H3 확인**
- Playwright 3명 완주(레이즈·올인 포함)
- 데스크톱 한 화면, 모바일 360·390 가로 넘침 0
- 홀덤 카드가 트럼프 그림으로 나오고, 족보 패널이 홀덤 목록임
- 검증 페이지 "일치"
- 다른 게임 회귀 없음

## 남은 질문
- 없음. 표준과 다르게 정한 점은 모두 **[우리 규칙]**으로 표시했고 규칙 문서에도 적는다: 짧은 올인 합산 안 함, BB보다 적은 첫 올인 뒤 최소 레이즈, 데드 버튼 없음, 남는 칩은 가장 낮은 좌석, 최소 바이인 10 BB.
