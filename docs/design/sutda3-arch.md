# 설계: 3장 섯다 방 + 게임 방식 선택

- 작성일: 2026-10-02 (rev.2: 1차 평가 "보통" 반영. 기한 재설정, 고른 카드 보관·노출, 변경 지점 목록, 참여 범위, 완료 기준)
- 관련 문서: [방 설계](rooms-arch.md), [게임 규칙](card-games-rules.md)의 2장 섯다, [블랙잭 설계](blackjack-arch.md)의 어댑터 구조
- 사용자 확정 사항:
  - 보류했던 3장 섯다와 홀덤을 **둘 다** 만든다. **3장 섯다가 먼저**다.
  - 방을 만들 때 **게임을 고르면 방식을 고른다**. 섯다는 2장/3장, 포커는 세븐포커/홀덤이다.
- 범위:
  - 3장 섯다 엔진, 서버 연결, 화면, 검증을 만든다.
  - 방 만들기에 방식 선택을 넣는다. 홀덤은 "준비 중"으로 표시만 하고, 구현은 다음 설계에서 한다.

## 결정 1. 3장 섯다 진행 규칙

출처는 [나무위키 섯다](https://namu.moe/w/%EC%84%AF%EB%8B%A4)다. "2장을 먼저 받고, 그중 1장을 오픈한다. 이 상태에서 베팅을 진행한 다음, 1장을 더 받고, 다시 베팅한다." 3장 중 2장으로 족보를 만든다. 공개할 패는 직접 고른다(대부분의 플랫폼 방식).

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. 2장 받음 → 공개할 1장 고름(동시) → 1차 베팅 → 1장 더 받음 → 쓸 2장 고름(동시·비공개) → 2차 베팅 → 쇼다운** | 출처와 같다. 2차 베팅 때 각자 자기 족보를 안다. 포커 초이스 방식을 재사용할 수 있다. | 동시 선택 단계가 2개 생긴다. |
| B. A와 같지만 공개 카드가 없다 | 단계가 하나 준다. | 출처의 핵심인 공개 패가 빠진다. |
| C. 쇼다운에서 최고 조합을 자동으로 쓴다 | 고를 필요가 없다. | 땡잡이·암행어사·구사는 평소 값이 낮아 절대 뽑히지 않는다. 전략이 사라진다. |

**추천: A.** 상세 규칙:
- **딜 순서**: 처음 2장은 **보스부터 한 장씩 두 바퀴** 돌린다(`dealOne` × 2). 3번째 카드도 보스부터 한 장씩 돌린다. 모든 카드는 숨긴 채로 받는다.
- **참여 범위**
  - `open`(공개 선택)은 **이번 경기 참가자 전원**이 한다. 재경기 재참여자와 올인한 사람도 포함한다.
  - `pick`(조합 선택)은 **다이하지 않은 참가자 전원**이 한다. 올인한 사람도 포함한다.
  - 다이한 사람, 재경기에서 빠진 사람, 범위 밖의 사람이 고르려고 하면 오류다.
  - 완료 조건은 `chosen.length === 대상 인원`이다.
- **공개 선택 `open`**: 2장 중 1장을 고른다. 전원이 정하면 그 카드들이 동시에 앞면이 된다. 정하기 전까지는 "누가 정했는지"(`chosen`)만 공개하고, 무엇을 골랐는지는 숨긴다.
  - **[우리 규칙]** 기한(15초)이 지나면 월이 낮은 카드를 공개한다. 같은 월이면 일반패를 공개한다.
- **1차 베팅**: 기존 한국식 베팅과 보스 규칙을 그대로 쓴다. 1차 베팅에서 1명만 남으면 `pick` 없이 바로 끝난다(기존 `advance` 규칙).
- **조합 선택 `pick`**: 3장 중 쓸 2장을 고른다. 공개한 카드를 버려도 된다. 공개는 정보를 내보이는 것일 뿐 그 카드를 써야 한다는 뜻이 아니다.
  - 고른 내용은 **쇼다운 전까지 본인만** 안다. 2차 베팅 중에도 남에게는 보이지 않는다.
  - **[우리 규칙]** 기한이 지나면 가능한 세 조합 중 평소 값(`evaluate().value`)이 가장 높은 것을 쓴다. 값이 같으면 각 조합을 카드 번호 오름차순으로 정렬해 사전순으로 비교하고, 앞선 조합을 쓴다.
- **2차 베팅 → 쇼다운**
  - 살아 있는 사람들의 **고른 2장만** 앞면으로 바꾸고, 그 2장으로 기존 판정(잡기·구사 재경기·동점)을 적용한다.
  - 숨긴 채 버린 카드는 뒷면 그대로 둔다(판이 끝난 뒤 검증 공개 때만 드러난다).
  - 공개했다가 버린 카드는 이미 앞면이다. 그래서 어느 2장을 썼는지 `used: Record<id, [a, b]>`로 공개 상태와 재경기 기록(`SutdaShowdown`)에 남긴다.
- **재경기**: 구사·동점·재참여 규칙은 2장 섯다와 같다. 재경기도 3장 흐름 전체(공개 선택부터)를 다시 한다. 재경기 3회 한도도 같다.
- **카드 수**: 6명 × 3장 = 18장 ≤ 20장. 덱 하나로 충분하다.

**리스크**: 한 판이 길어진다(선택 기한 15초 × 2). 화면 문구로 지금 무엇을 고르는 중인지 분명히 보여 준다.

## 결정 2. 엔진 구조

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. 기존 섯다 엔진에 `variant: 2 \| 3` 추가 + 페이즈 `open`·`pick` 추가** | 족보·판정·팟·재경기·재참여를 그대로 재사용한다. | `game.ts`가 커지고, 2장 섯다가 회귀할 위험이 있다. |
| B. `sutda3/game.ts`로 따로 만든다 | 2장 섯다 코드에 손대지 않는다. | 재경기·팟 정산 코드(약 200줄)가 중복된다. |

**추천: A.** 바뀌는 함수와 상태는 다음과 같다.

| 위치 | 변경 |
|---|---|
| `SutdaState` | `variant?: 2 \| 3`. 없으면 2로 본다(진행 중이던 예전 상태 호환). `chosen?: string[]`, `used?: Record<string, [number, number]>`. 모두 선택 필드이고 variant 3 경로에서만 읽는다. |
| `secrets` | `opens?: Record<id, card>`(전원 확정 전), `picks?: Record<id, [a, b]>`(쇼다운 전) |
| 새 페이즈 | `SutdaPhase`에 `"open"`·`"pick"`을 추가한다. |
| 새 액션 | `{type:"open", seatId, card}`, `{type:"pick", seatId, cards:[a,b]}`, `{type:"choice_timeout"}`(두 페이즈 공통) |
| `createSutdaHand` | `p.variant`를 받는다. 3이면 `dealOne` × 2를 한 뒤 `open` 페이즈로 시작한다(베팅 라운드는 아직 시작하지 않는다). |
| `startRematch` | variant 3이면 `dealOne` × 2 → `open`으로 간다(`beginRound`는 공개 뒤에). 이때 `chosen = []`로 비우고, `used`와 `secrets.opens`·`secrets.picks`를 지운다. 지난 경기의 `used`는 `history`에만 남긴다. |
| `advance` | variant 3의 `bet1`이 끝나면 `dealOne` → `pick` 페이즈로 간다. `pick`이 끝나면 `beginRound`(bet2)로 간다. |
| `chosen` | `open`에서 `pick`으로 넘어갈 때 **초기화**한다(두 단계가 같이 쓴다). |
| `reduceSutda` | **페이즈를 먼저 검사**한다. `open`·`pick` 중에는 그 단계 액션과 `choice_timeout`만 받는다. 베팅 액션은 `bet1`·`bet2`에서만 받는다. |
| `handsOf`·`showdown` | variant 3이면 `secrets.picks`로 평가하고, 앞면은 고른 2장만 바꾼다. `used`를 채우고 `history` 기록에 `used`를 함께 넣는다. |
| `viewSutda(state, viewerId)` | `secrets`는 계속 지운다. 대신 **본인 것만** `myOpen`(내가 확정한 공개 카드)과 `myPick`(내가 고른 2장)으로 따로 내려 준다. 남의 선택은 어디에도 없다. |
| 덱 생성 `sutdaDecks` | 바꾸지 않는다(RNG v1 그대로). |

2장 섯다 회귀 방지: 기존 섯다 단위 테스트와 퍼즈 테스트 전부, 그리고 **예전 2장 판 기록의 재생 결과가 같아야** 통과로 본다.

## 결정 3. 방 종류 저장 (방식 선택)

| 옵션 | 장점 | 단점 |
|---|---|---|
| **A. `rooms.game`에 `sutda3` 추가 (이후 `holdem`)** | 기존 분기에 값만 늘리면 된다. 마이그레이션은 체크 제약 하나다. | 화면에서 "섯다 계열"로 묶는 매핑이 필요하다. |
| B. `rooms.variant` 컬럼 신설 | 게임과 방식을 따로 표현한다. | 서비스·뷰·검증·목록 전부에 컬럼이 늘어난다. |

**추천: A.**
- `GAME_KINDS = ["sutda", "sutda3", "poker7", "blackjack"]`. 엔진 상태는 `game: "sutda"`, `variant: 3`이다. `createGame`에서 방 종류를 보고 `variant`를 넣는다. `createRoom` 검증과 `minPlayers`는 `GAME_KINDS`를 늘리면 따라온다. `summarize`는 엔진 `game`이 `"sutda"`라 그대로 쓴다.
- 마이그레이션 `20261002000010_sutda3_rooms.sql`: `rooms_game_check`에 `sutda3`를 추가한다.

### 서비스·어댑터 변경 지점
| 위치 | 변경 |
|---|---|
| `games.ts` `waitKind` | `"open"`과 `"pick"`을 **따로** 돌려준다. 1차 베팅이 바로 끝나서(전원 올인) `open` 다음에 곧장 `pick`이 와도 `prevWait !== wait`가 되어 **기한을 새로 잡는다**. |

## 결정 4. 화면

- **방 만들기**: 게임(섯다 / 포커 / 블랙잭)을 고르면 그 옆에 **방식**을 고른다.
  - 섯다: 2장 / 3장. 포커: 세븐포커 / 홀덤. 블랙잭은 방식이 없다.
  - 홀덤은 구현 전까지 "홀덤 (준비 중)"으로 비활성화한다. `create-room-form.tsx`의 상태 타입과 선택지를 바꾼다.
- **라벨**: 방 목록(`rooms/page.tsx`)과 방 제목(`room-table.tsx`)에 "2장 섯다 / 3장 섯다 / 7포커 / 블랙잭"을 보여 주는 매핑 하나를 쓴다. 모르는 값을 "섯다"로 보여 주던 기존 방식을 없앤다.
- **3장 섯다 판**
  - `open`: 내 2장 위에 "공개할 카드를 누르세요"를 띄운다. 누르면 표시되고 [확정]을 누르면 낸다.
  - `pick`: 내 3장 위에 "쓸 2장을 고르세요"를 띄운다. 2장을 고르면 그 조합의 족보 이름을 미리 보여 주고 [확정]을 누르게 한다. 확정한 뒤에는 `myPick`으로 고른 2장을 표시한다.
  - 다른 사람 자리: 공개 카드만 앞면이고 나머지는 뒷면이다. 정한 사람에게는 "고름" 배지를 붙인다.
  - 쇼다운: 각 자리에서 `used`의 2장을 강조하고, 버린 카드는 흐리게 보여 준다.
- **족보 패널**(`hand-ranks.tsx`): `sutdaPosition`을 3장까지 받게 바꾼다. `HandRanks`와 `myHandLabel`에 variant(또는 카드 수)를 넘긴다.
  - `pick` 전: 3장으로 만들 수 있는 조합 중 평소 값이 가장 높은 것을 "가능한 최고"로 강조한다. 특수패 4종(땡잡이·암행어사·구사·멍텅구리구사)은 평소 값이 낮아 여기에 나오지 않는다. 그래서 그 조합이 가능하면 특수패 줄에 따로 "가능"으로 표시한다.
  - `pick` 후: 고른 조합을 강조한다.
- **검증 페이지**: `revealed.game === "sutda3"`이면 variant 3으로 재생하고 덱 설명 문구도 3장 순서에 맞춘다. 타입(`RevealedHand.game`)에 `sutda3`를 추가한다. 값이 없거나 `"sutda"`인 예전 판은 그대로 2장으로 재생한다.
- 한 화면 맞춤과 모바일 가로 넘침 0 기준은 그대로다. 카드가 3장이라 겹칠 필요가 없다.

## 구현 단계 (단계마다 평가해서 통과해야 다음 단계로 간다)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| S1 | 엔진 + 테스트 | 고정 덱 시나리오를 모두 통과해야 한다. **기존 2장 섯다 테스트 전부 통과.** <br>· 딜 순서(보스부터 두 바퀴) <br>· 공개 선택이 확정 전에는 남의 view에 없고, 전원 확정 시 동시 공개 <br>· 1차 베팅에서 1명만 남으면 `pick` 없이 종료 <br>· 올인한 사람도 `pick` <br>· 다이했거나 빠진 사람의 `pick`, 남의 카드, 중복 카드, 잘못된 단계의 액션은 거부 <br>· 2차 베팅 중 남의 view에 고른 카드가 없고 본인 view에는 `myPick`이 있음 <br>· 공개 카드를 버리는 조합 <br>· 쇼다운 뒤에도 숨긴 채 버린 카드는 `null`, `used`가 맞음 <br>· 시간 초과 자동 규칙 두 가지(동점일 때 포함) <br>· 땡잡이를 직접 골라 잡기 성공 <br>· 구사 재참여 + 재경기가 3장 흐름으로 진행, 재경기 3회 한도 분배 <br>· `variant` 없는 예전 상태로 진행 중이던 판을 이어서 진행 <br>· 예전 2장 판 기록을 재생하면 같은 지급 <br>퍼즈 테스트: 결정성, 보존 |
| S2 | 마이그레이션 + 어댑터·서비스·API | DB 테스트: 3명 완주, 보존식, 동시 tick 1회, 남의 응답에 선택 없음, **1차 베팅이 생략돼도 `pick` 기한이 새로 15초**, 선택 시간 초과 횟수 → 자동 일어서기. 기존 DB 테스트 전부 통과 |
| S3 | 화면 + 검증 페이지 + 문서 | Playwright 3명 완주. 데스크톱은 한 화면, 모바일 가로 넘침 0. 족보 패널이 3장을 표시하고, 방 목록·제목 라벨과 검증 덱 문구가 맞고, 검증 "일치". 2장 섯다·7포커·블랙잭 회귀 없음 |
| S4 | 배포 (/careful) | 원격 마이그레이션, 운영에서 1판 |
